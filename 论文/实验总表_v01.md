  在系统层证据稳定后，再引入学习化评分/二阶段模型作为增强而非替代。

## Part D｜路线分叉判断

- 当前应先走**系统强化路线（E4~E8）**，原因：
  1) E1/E2/E3 仅在单 run、有限 collector 下完成；
  2) 主链可解释口径已成型，但稳健性与泛化证据仍不足；
  3) 论文主张 A/B/C 目前更依赖系统层验证而非模型复杂度。

- 为什么算法增强路线不应立刻全开：
  - 若先上学习模型，会把“系统是否稳定”与“模型是否有效”混在一起，难以归因；
  - 当前还缺多 run 稳定性、参数敏感性、消融证据，直接引入模型会稀释主线。

- 触发 E9（学习化评分层）的条件：
  1) E4~E8 完成且主链指标在多 run 下稳定；
  2) 规则评分层瓶颈被明确定位（例如排序能力不足或特定场景误差集中）；
  3) 有可复用训练/验证口径，不破坏现有 final 三类解释框架。

- 为什么评分层是最优先学习化插入点：
  - 位于候选与门控之间，输入输出边界清晰；
  - 可保持候选规则与门控/增强逻辑不变，改动面最小，归因最清楚；
  - 与 `risk_score` / `risk_bucket` 口径天然对齐，替换成本低。

- 为什么不建议直接端到端深度学习替换：
  - 现阶段样本规模、标签质量与实验边界不足以支撑端到端泛化结论；
  - 会损失当前链路的可解释层次（candidate/gating/augmentation explanation）；
  - 工程与写作风险都显著上升，不利于当前阶段收敛。

## Part E｜下一阶段执行顺序

执行顺序：
1. E4（多 run / 多时间窗口稳定性）
2. E5（关键参数敏感性）
3. E6（模块消融）
4. E7（collector / 可观测性影响）
5. E8（案例分析）
6. Gate 判断（是否满足算法增强触发条件）
7. 再决定是否进入 E9 / E10

为什么这个顺序最合理：
- E4 先验证“是否稳定”；
- E5/E6 再验证“为什么有效、是否稳健”；
- E7 补“可观测性边界”；
- E8 把量化结果转成可解释案例闭环；
- 完成后再做 Gate，可避免过早进入学习化路径。

需要重新判断路线的节点：
- **E6 完成后**做一次中期判断（若消融证据弱，先修系统口径）。
- **E8 完成后**做最终 Gate（决定 E9/E10 是否启动）。
