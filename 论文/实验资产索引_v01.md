# 实验资产索引_v01

> 角色：BGP-EXP 实验资产导航图  
> 用途：同时服务于后续实验推进、系统完善、论文写作与对外汇报。  
> 维护原则：只记录“正式可复用资产”和“需要明确避坑的过渡资产”，避免目录越来越多后找不到正式版本。

## 1. 使用规则

- 开始新实验前，先读：
  1. `论文/实验总表_v01.md`
  2. `论文/实验资产索引_v01.md`
  3. 若涉及已知事件，再读 `data/known_events/known_event_candidates_v05.json`
- 默认只引用本索引中标记为“正式资产”的目录与文件。
- 对同一实验存在多个版本时，优先使用本索引明确指定的正式版本；不要凭目录名猜。
- 带有 `local`、`check`、临时调试含义的目录，默认不作为论文或后续实验的正式输入。
- 每次新实验收口后，至少同步两处：
  - `论文/实验总表_v01.md`
  - `论文/实验资产索引_v01.md`

## 2. 固定总入口

### 2.1 时间线总账

- `论文/实验总表_v01.md`
- 用途：看“我们按时间做了什么、结论是什么、产物在哪”。

### 2.2 实验资产导航

- `论文/实验资产索引_v01.md`
- 用途：看“正式资产到底是哪一版、后续要复用什么、哪些目录不要误用”。

### 2.3 新对话接手背景

- `runs/prism_handoffs/2026-04-08_experiment_context_v1.md`
- 用途：给新对话快速接入，不替代正式总账。

### 2.4 已知事件主清单

- `data/known_events/known_event_candidates_v05.json`
- 用途：统一维护已知事件的类型、锚点、时间窗、优先级与口径。
- 当前默认口径：
  - forged-origin / more-specific：`exact_prefix`
  - route-leak：优先 `ordered_leak_chain`
  - `Indosat` 当前按 route-leak 风格样本解释

### 2.5 已知事件当前库存快照

- `outputs/e9c_known_event_inventory_v05/`
- 核心文件：
  - `e9c_known_event_inventory.csv`
  - `e9c_known_event_inventory.md`
  - `e9c_known_event_inventory_summary.json`
- 用途：看当前 7 个公开已知事件在 baseline / expanded 下的最新总体状态。

## 6. 当前默认引用顺序

如果后续我要继续做实验，默认按下面顺序查：

1. 看 `论文/实验总表_v01.md`
2. 在 `论文/实验资产索引_v01.md` 找正式目录
3. 若涉及公开已知事件：
   - 先看 `data/known_events/known_event_candidates_v05.json`
   - 再看 `outputs/e9c_known_event_inventory_v05/`
4. 若涉及 route-leak 评估：
   - 优先查 `outputs/s0_dual_track_eval_v02/`
   - 再查 `outputs/e9d_route_leak_gap_audit_v01/`、`outputs/e9e_google_verizon_chain_audit_v01/`
5. 若涉及 backup 历史事件：
   - 先看 `outputs/e9f_backup_visibility_v01/`
   - 再看 `outputs/e9i_pakistan_time_window_audit_v01/`
